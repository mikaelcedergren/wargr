# wargr.com

Michael Wargr's essays — an **Angular 22 SSG site built on `@mikaelcedergren/cx-framework`** (light
theme default), prerendered to static HTML and served by a small Express server on the Mac mini, the
**same architecture as the other static sites**. Substack-like reading design. **No CodeKit.**

The articles are NOT authored here. They are pulled from the **ghostwriter** repo
(`../ghostwriter/wargr/*.md`) at build time. This repo is the presentation layer only.

## Publishing rule (important)

A ghostwriter essay is **published only if its filename starts with `☑`** (e.g. `☑ corruption.md`).
Every other file is a draft and is skipped. To publish a piece, add `☑ ` to its filename in
ghostwriter; to unpublish, remove it. This is handled automatically (see Auto-sync).

## Run

```bash
pnpm install
pnpm import     # regenerate Angular pages from ../ghostwriter (☑-marked essays)
pnpm dev        # import + ng serve at http://127.0.0.1:4260
pnpm build      # import + ng build (prerender) -> dist/browser, then flatten
pnpm start      # serve dist/browser at http://127.0.0.1:3060 (HOST/PORT env; health: /healthz)
```

## Architecture

Angular 22 standalone, prerendered to static HTML (`outputMode: static`, every route
`RenderMode.Prerender`), served by the shared server library (`../../server-ops/lib/site-server.mjs`).
cx-framework provides the design language (tokens, colours, type, spacing); `src/styles.scss` adds a
long-form reading layer on top (the framework's type scale is app-sized).

```
src/
  index.html                <html class="theme-light">; Inter font; <wg-root>
  styles.scss               cx-framework tokens + base + the wg- reading/layout styles (light)
  app/
    app.component.*          masthead ("Wargr" / Michael Wargr) + <router-outlet> + footer
    app.routes.ts            GENERATED by scripts/import-articles.mjs (home + one route per essay + 404)
    pages/home.component.ts  GENERATED feed: title + dek + date per essay
    pages/not-found.component.ts
    articles/<slug>.component.ts  GENERATED per essay; body rendered via [innerHTML]
    shared/seo.ts            SeoTitleStrategy: title/desc/canonical/OG/Twitter/JSON-LD (BlogPosting)
public/{robots.txt,sitemap.xml}  GENERATED by the importer
scripts/import-articles.mjs ☑-filter, parse (title/ingress/body/tags/git-date), markdown->HTML (marked)
server/index.mjs            Express static server (shared lib; /healthz; SSG directory-index serving)
bin/sync-from-ghostwriter   rebuild script (guarded by a signature of the ☑ set)
launchd/com.wargr.server.plist   web service (port 3060)
launchd/com.wargr.sync.plist     WatchPaths(../ghostwriter/wargr) + 2-min poll -> sync-from-ghostwriter
```

### Article parsing

Each ghostwriter file: `# Title` / `## Topic:` (internal, ignored) / `---` / `**ingress**` + body /
`---` / tags + social + thumbnail prompts. The importer takes the **title**, the **ingress** (the
bold line — used as the reader-facing dek + meta/OG description), the **body** (markdown between the
two `---`, rendered to HTML), the **tags** (→ keywords), and a **date** from git history. Slug =
filename minus `☑` and `.md`. URLs: home `/`, each essay `/<slug>/`.

## Auto-sync from ghostwriter

`com.wargr.sync` watches `../ghostwriter/wargr` (instant on add/remove/rename, e.g. a `☑` toggle)
plus a 2-min safety poll for in-place edits, and runs `bin/sync-from-ghostwriter`. That script only
rebuilds when the **published (`☑`) set's signature** changes (names + mtimes + sizes), so editing a
draft never triggers a build. The running web service serves `dist/browser` from disk, so a rebuild
needs **no restart** — new content appears within ~the micro-cache TTL (60s).

## cx-framework

Genuinely consumed: `@use '@mikaelcedergren/cx-framework/tokens'` + `/styles/base` in `src/styles.scss`,
light theme (`theme-light`, the framework default). Fix design issues upstream in cx-framework, not here.
